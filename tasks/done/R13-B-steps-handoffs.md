# R13-B: persist crew steps, handoffs and totals; wire Crews steps/handoffs/runMetrics
- **Owner:** executor (Python + Rust + TS logic). Design doc §8, §11 Phase B. HANDOFF types: CrewRunRow, CrewStep, CrewHandoff.
## Acceptance criteria
- [x] crew-service: tables `crew_steps` (id, run_id, agent role id, kind task|tool|llm, label, start_ms, end_ms, status ok|failed|skipped) and `crew_handoffs` (run_id, from, to, status); `crew_runs` gains finished_at, tokens, requests (cost_usd 0 for local). Idempotent migrations (existing rows untouched).
- [x] The role runner emits a step when a task / tool / LLM call starts and ends; a handoff when one role's output feeds the next. Labels are short ("researcher: task", "tool: kb_query", "llm: analyst"): **no prompt text, completions or secrets**; tool error text redacted with the existing sanitize_error.
- [x] Totals: tokens = prompt + completion from the LLM responses (router usage), requests = LLM calls, finished_at on completion/fail/stop.
- [x] API: `GET /crews/runs/{id}/steps` → { steps, handoffs } (empty arrays if none), behind X-Crew-Token, loopback; `/crews/list` and `/crews/status` include the optional totals.
- [x] Tauri: `crew_run_steps(id)` in crew.rs (validated id, same client/auth as crew_status); extended CrewInfo optional fields. Register + bridge wrapper.
- [x] Crews adapter (`src-console/crews/adapters.ts` live picker; logic only, Design-owned file): `steps(runId)`, `handoffs(runId)`, `runMetrics(runId)` return live data when loaded (async source loaded into a hook/cache the adapter reads); unwired otherwise; never invented numbers. Check the exact interface shapes in adapters.ts (startPct/endPct/took etc.) and map from start_ms/end_ms.
- [x] Tests: a mocked two-role run yields a timeline and one handoff; labels contain no prompt text; a secret in a tool error is redacted; Rust id validation; vitest adapter mapping and unwired-when-empty.

## Evidence (executor, uncommitted)
- crew-service: crew_steps/crew_handoffs tables + `ALTER ... ADD COLUMN IF NOT EXISTS tokens/requests` (additive, idempotent; finished_at already existed). `RunRecorder` in the crew child uses crewai's event bus (task + LLM events, timestamps from the events) and times tool calls in `_to_crewai_tool`; dict messages go over the existing pipe, parent `_watch` drains it live and writes rows via `db_add_step/db_add_handoff` (kind/status allowlisted, label capped, error via sanitize_text), totals via `db_set_totals` on every exit path (stop/timeout keep what was used). `GET /crews/runs/{id}/steps` (token-gated, uuid-validated, 404 unknown run, empty arrays if none). CrewInfo gains finished_at/tokens/requests/cost_usd (cost 0.0 for router runs, null for minimax/unknown).
- Tokens: exact per LLM call from `LLMCallCompletedEvent.usage` (prompt+completion; input/output names also read). Calls with no usage are counted in `usage_missing`, logged, and then the crew's own `token_usage` total is used if higher; never estimated. Verified only against the mock router (2 tokens/call); real router usage fields not verified live (container not rebuilt/restarted, per instructions).
- Handoff: derived from the fixed task order (task N starts after N-1), one per adjacent pair, status ok. Not recorded as failed when the earlier task fails (that task's step is failed and later tasks are skipped).
