# 1110i: per-crew Files / terminal switch, enforced in crew-service

Files: `stack/crew-service/crew_grants.py`, `test_grants.py`, `main.py` (tools, approvals kind `tool_grant`, endpoints, sweeper); `src-tauri/src/commands/crew_grants.rs` (`crew_tool_grant_get/set/revoke`, `crew_tool_audit`); `src-console/bridge.ts`, `crews/toolGrantLive.ts`; compose has commented mount examples only.

## Contract implemented
- Default OFF, fail closed: no grant row = `fs_read`/`fs_write`/`shell` rejected even if a role names them; unset `CREW_SANDBOX_ROOT` = the tools are not registered at all.
- Scope: `CREW_SANDBOX_ROOT/<slug(crew)>` (host `~/crew-sandbox/<crew>`; TAISUN mounts it). realpath checks, symlink escape and `..` rejected and audited as `blocked`; `.git` off limits.
- Duration: "this run only" (default, bound to the first run after the grant and ended with it), `1h`, `24h` cap. No "until off". Requests expire after 1 h. Expiry is checked on every call and every 0.5 s while a command runs, plus a 30 s sweeper that audits it; revoke or expiry kills the running child (SIGTERM, then SIGKILL).
- Only `granted_by: "taisun"` creates a grant (anything else 403 and audited); a crew can only `request_tool_grant`, which raises a High-risk Crews approval; a denial answers the tool and the run continues. Turning ON from the app goes through the native dialog; crew-service must confirm the enforced allowlist within 15 s or it stays off.
- Writes and commands still need the batch approval when on (the grant precheck runs first so nobody approves something that cannot run). Git checkpoint before the first write of a run (short hash stored on the audit row; refused if git fails).
- **Terminal allowlist (security review):** plain file utilities only (ls cat head tail wc grep sort uniq diff echo pwd mkdir touch cp mv rm date true false) plus read-only `git status|diff|log` with hooks/fsmonitor/pager/protocol/external-diff disabled and a scrubbed env. No python, pytest, sh/bash, env, xargs, find, awk, sed, node or other interpreter/exec tool; no git commit/add/push/fetch. Every option comes from a per-program grammar (unknown flags refused; clusters only of known booleans); every option value (`-oX`, `--output=X`, `-o X`) and positional resolves inside the folder after symlinks and `..`; programs by name only. Network, git push, sudo, spending are not representable.
- Audit: in-app trail only (no CSV): actor, crew, run, kind, short redacted target, exit code, duration, checkpoint. No output, prompt text or secrets.
