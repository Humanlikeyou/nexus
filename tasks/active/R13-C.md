## Design choices
- Evidence is built only by the loop: `test_output` (exit 0, command listed on the task), `review` (reviewer role differs from the task role, rests on a recorded passing test result), `approval` (a UUID from a real approval). Free text is never evidence.
- **Security decision (coordinator review):** the container has network and no sandbox, so an interpreter is unrestricted network. The verification runner therefore executes NOTHING by default: `run()` raises `NeedsApproval`, the task goes `awaiting_approval`, and it can only succeed with an approval id as evidence (never a fake test result). Execution needs BOTH `CREW_VERIFY_EXEC=1` and `CREW_VERIFY_NO_NETWORK=1`, set by an operator who runs the container with no network. Neither is set in the image or compose. Grammar validation (plan check) still works without executing.
- The crewai-backed `Runners` (planner/executor/reviewer turns) are an interface plus fakes in tests; `/crews/start` still runs the existing sequential crew. Wiring the loop to crewai needs a live model: not run.
